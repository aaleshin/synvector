# Synvector Stellaris-style Landing

Лендинг игры **Synvector** на React 18, Vite 5 и Tailwind CSS 3.
Это клиентский одностраничный сайт: описание игры, команда, трейлер, FAQ,
подписка и юридические окна. Серверной части и базы данных в проекте нет.

## Быстрый запуск (Quick Start)

Нужны Node.js и npm. Для Vite 5 используйте совместимую версию Node.js
(18 или 20+; предпочтительнее поддерживаемую LTS-версию).
Команды выполняются из корня проекта:

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite, обычно <http://localhost:5173>.
Если зависимости нужно установить строго по `package-lock.json`, вместо
`npm install` используйте `npm ci`.

## Интерфейс (Interface)

| Файл / символ | Назначение |
| --- | --- |
| `src/App.jsx:App` | Экспорт по умолчанию; выводит компонент страницы. |
| `src/GameLanding.jsx:GameLanding` | Экспорт по умолчанию; задаёт порядок секций, навигацию и состояние окон Privacy/Terms. |

## Надписи на сайте, переходы и имена компонентов

**Это карта соответствий для редактирования кода, а не список ошибок
навигации.** Надпись кнопки, заголовок секции, HTML-идентификатор (`id`)
и имя React-компонента — разные вещи. В текущем коде все четыре пункта
верхнего меню направлены к соответствующему содержимому.
Все перечисленные компоненты находятся в
[`src/GameLanding.jsx`](./src/GameLanding.jsx).

### Верхнее меню: что написано и куда ведёт

Кнопки находятся в `Header`, их подписи и целевые `id` заданы в
`GameLanding:nav`. Нажатие вызывает плавную прокрутку через `scrollToEl`,
а не открывает другую страницу и не меняет адрес в строке браузера.

| Надпись кнопки | Куда прокручивает | Заголовок целевого блока | Компонент целевого блока | Пояснение имени |
| --- | --- | --- | --- | --- |
| `About` | Секция `id="about"` | `About the game` | `SocialButtons` | Имя означает «кнопки соцсетей», но сейчас компонент выводит описание игры, без соцкнопок. Переход правильный. |
| `Our Team` | Секция `id="team"` | `Experienced team you can trust` | `About` | Имя общее («о нас»), а содержимое — команда. Это не блок `About the game`. Переход правильный. |
| `Trailer` | Секция `id="media"` | `Watch the Trailer` | `Media` | Общее имя «медиа» используется для блока трейлера. Переход правильный. |
| `FAQ` | Секция `id="faq"` | `FAQ` | `FAQ` | Надпись, содержимое и имя компонента совпадают. |

### Важно: MEDIA не является единым источником контента

В текущем коде `MEDIA.socials`, `MEDIA.supportedBy` и `MEDIA.logos.footer`
управляют соответствующими видимыми элементами. Однако:

- `MEDIA.hero` и `MEDIA.logos.header` / `hero` используются для предзагрузки,
  но видимые фон и логотип `Hero` заданы прямо в JSX.
- `MEDIA.infoBlocks` не используется компонентом `InfoBlocks`:
  редактируйте тексты непосредственно в его разметке.
- `MEDIA.trailerYouTubeId` используется компонентом `Media`: смена ID меняет
  и адрес iframe, и постоянную ссылку под ним.
- `MEDIA.logo` не подключён к отображению страницы.
- `InfoRow` и несколько вспомогательных компонентов объявлены, но сейчас
  не выводятся; правки в них сами по себе не изменят страницу.

### Как заменить или добавить медиа

1. Положите файл в [`public/media/`](./public/media/).
2. В нужном компоненте укажите адрес вида `/media/имя-файла.webp`
   или `/media/имя-файла.mp4` — **без** префикса `public`.
3. Соблюдайте регистр и расширение: `Logo.png` и `logo.png` — разные пути
   на регистрозависимом хостинге.
4. Проверьте загрузку файла в браузере и вкладке Network.
   Успешная сборка не гарантирует наличие медиа по строковым URL.

В `media/` есть MP4/WebM, иллюстрации `image *.png`, корабли, логотипы,
портреты `Ellipse *.png` и слайды `slide*.webp`.
Папка `media/pp/` содержит дополнительные WebP-портреты; текущий массив
`About.people` ссылается на PNG из самой `media/`, а не из `pp/`.
Не все имеющиеся медиа используются страницей.

### Трейлер и ручной возврат

`Media` создаёт iframe на `youtube-nocookie.com` однократно, когда область
плеера приблизилась к окну на 300px. До этого остаются тёмная область 16:9
без внешней миниатюры и постоянная ссылка `Watch on YouTube`.
Уход из секции не удаляет iframe и не сбрасывает позицию воспроизведения.
При отсутствии `IntersectionObserver` iframe создаётся сразу, без автозапуска,
а секции показываются без анимации.

Старый `<video>` с путём `/media/Synvector_02-2.mp4` сохранён в JSX-комментарии;
MP4 остаётся на диске. Для возврата вручную убрать активный iframe
и его эффект загрузки, затем раскомментировать старый плеер.
Фича-флага и автоматического переключения нет.
Доступность встраивания и воспроизведения нужно проверять в браузере:
внешняя ссылка сама по себе не подтверждает работоспособность плеера.

### Известные ограничения текущей реализации

- `Header` переключает `mobileOpen`, но разметки раскрывающегося мобильного
  меню нет. На узком экране кнопка есть, а пункты меню не появляются.
- `Newsletter` содержит поле email и кнопку, но не имеет обработчика
  отправки или вызова API. Ввод адреса не оформляет подписку.
- В сохранённом неактивном локальном `<video>` для `poster` указан MP4.
  Это свойство старого варианта в комментарии, не ошибка нового iframe.
- По дополнительному согласованию из описания `Hero` удалено `co-op`;
  остальные слова сохранены. Старый `Play Co-op` остаётся только
  в неиспользуемом `MEDIA.infoBlocks`, который не выводится на странице.
- Есть ссылки на отсутствующие файлы: например,
  `MEDIA.hero.poster` → `/media/hero-poster.jpg`,
  а favicon в `index.html` → `/media/Synvector_Logo_symbol.png`
  и `/media/favicon.svg`. В каталоге есть `Synvector_Logo_symbol.webp`,
  но это другой путь. Учитывайте это при проверке Network.
- Основной шрифт `body` — Mulish из CSS. В `index.html` дополнительно
  подключён Oswald; комментарий в CSS не отражает фактический шрифт `body`.

## Инварианты (Invariants)

При изменениях сохраняйте следующие связи, на которые опирается код:

- `index.html:#root` должен соответствовать
  `src/main.jsx:document.getElementById('root')`.
- `GameLanding:nav` и `scrollToEl` используют идентификаторы секций:
  сейчас `about`, `team`, `media`, `faq`. При переименовании меняйте обе стороны.
- `Header` выбирает YouTube, Reddit и Discord по точному `MEDIA.socials.label`;
  `Hero` ищет Steam по точной строке `"Steam"`. Для новой соцсети недостаточно
  только добавить запись: проверьте фильтр и отображение иконки.
- `About:people` ожидает `name`, `role` и необязательный `img`;
  ключ карточки — уникальное полное имя. `FAQ:faqs` — `q`, `a`;
  `Footer` использует `name`, `logo`, `href` из `MEDIA.supportedBy`.
- `tailwind.config.js:content` сканирует `index.html` и `src/**/*.{js,ts,jsx,tsx}`.
  Если разметка с классами появится вне этих путей, обновите настройку.

## Побочные эффекты (Side Effects)

- `GameLanding` читает `window.location.hash`, слушает `hashchange` и
  прокручивает страницу через `scrollIntoView`.
- Эффекты `GameLanding` добавляют в `document.head` ссылки предзагрузки,
  preconnect и `<style>`; при очистке удаляют добавленные элементы.
- `useInView` использует `IntersectionObserver` для повторяющихся анимаций
  появления; при очистке отключает наблюдатель. Без API сразу показывает
  секции, не создавая наблюдатель.
- `Media` отдельно наблюдает за областью плеера для однократной загрузки;
  отключает observer после срабатывания и при очистке. Загрузка iframe
  не управляется повторно переключаемым состоянием анимации.
- `index.html` и `src/index.css` подключают шрифты Google Fonts.
  Медиа загружаются браузером, а внешние ссылки ведут, в частности,
  на Steam, YouTube, Reddit, Discord и сайт партнёра.
- В текущем `Newsletter` нет отправки email; хранилище подписчиков и
  сохранение данных на сервере не реализованы.
- `package.json:build` запускает сборку Vite, которая создаёт/обновляет `dist/`.

## Сборка и проверка (Verification)

По умолчанию `npm run build` пишет в `dist/`. Если там есть пользовательские
изменения, используйте новый уникальный каталог за пределами репозитория.
Для текущей итерации — каталог внутри
`C:\Users\Asenok\AppData\Local\Temp\opencode`; подставьте реальный свежий путь:

```bash
npm run build -- --outDir "<полный путь к новой папке сборки>"
npm run preview -- --outDir "<тот же путь>" --host 127.0.0.1
```

Не добавляйте принудительную очистку и не используйте общую существующую папку.
Адрес просмотра берите из вывода Vite. При неподдерживаемом параметре preview
остановитесь, а не возвращайтесь молча к рабочему `dist/`.
Для публикации на статическом хостинге используется результат сборки;
эта итерация не включает публикацию или коммиты.
Пути `/media/...` в текущей разметке рассчитаны на корень домена:
размещение в подпапке требует отдельной проверки и настройки путей.

В `package.json` нет команд `test`, `lint` или форматирования.
Доступная автоматическая проверка — `npm run build`; она не заменяет
ручную проверку страницы.

После правок:

1. Проверьте изменённую секцию через `npm run dev`.
2. Посмотрите десктопную и мобильную ширину: переносы текста, размеры
   изображений, отсутствие горизонтальной прокрутки.
3. Проверьте якорную навигацию, ссылки, видео и окна Privacy/Terms.
4. Откройте Console и Network: исключите ошибки JavaScript и неожиданные 404.
5. Выполните безопасную сборку и просмотр с одинаковым внешним `outDir`, как выше.
6. Просмотрите `git diff`: правки должны касаться исходников и нужных ресурсов,
    а не случайных изменений зависимостей или сгенерированных файлов.
